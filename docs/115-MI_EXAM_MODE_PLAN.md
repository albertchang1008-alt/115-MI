## 1. 教學與施測安排

前測與後測是兩場獨立測驗，各7題單選，同概念配對、使用不同題目。保留已核可題幹、選項與正解；14題不放進閃卡、抽題、錯題複習、綜合練習或互動教材。

| 項目 | 前測 | 後測 |
|---|---|---|
| 時點 | 登入完成、教學開始前 | 兩案例教學結束後 |
| 預設作答時間（建議） | 8分鐘 | 8分鐘 |
| 卷別 | A卷，7題固定全出 | B卷，7題固定全出 |
| 作答方式 | 個別作答，不討論 | 個別作答，不討論 |
| 次數 | 每人一次正式交卷 | 每人一次正式交卷 |
| 作答後畫面 | 已交卷、交卷時間 | 已交卷、交卷時間 |
| 分數、正解、解析 | 預設暫不公布 | 預設暫不公布 |
| 公布時點 | 後測整場結束後由教師統一公布 | 同左 |

教師可調整時間並設定每班開放與截止；預設不以100分通關，不要求補答到全對。測驗成績獨立記錄；是否計入學期成績由教師決定，不能套用一般練習最高分或達標門檻。

原120分鐘主流程保留：0–12登入／前測，12–58細菌案例，58–68休息，68–108免疫案例，108–120後測／反思。每次8分鐘是建議值；只有伺服器端時間與正式發布的測驗設定決定有效期限。

## 2. 學生操作流程

1. 以本人Google帳號登入，確認已列入MI班級名冊。
2. 課程顯示獨立「前測」「後測」卡片：未開放、可開始、作答中、已交卷、缺考／逾時等狀態。沒有一般練習的「最高分／達標／再做一次」入口。
3. 考前說明顯示題數、限時、僅一次、如何處理斷線；學生按「開始測驗」才建立正式場次。
4. 逐題或列表作答；可在交卷前修改選項。顯示倒數與已作答題數；不顯示正誤、提示、答案或解析。
5. 每次選答保存到後端，畫面區分「已儲存」「儲存中」「尚未儲存」；不能把本機選取當成已收到。
6. 手動交卷前顯示未答題數並確認；允許空白交卷，空白以0分計。
7. 交卷成功後只顯示收件證明與時間，禁止再修改。重新整理仍回到同一正式場次，不取得第二次機會。
8. 教師公布結果後，學生才可查看自身分數與教師允許公開的正解／解析；前測不得先公布而影響後測。

教師預覽使用模擬場次，不寫入正式學生測驗紀錄。平台內隱藏練習入口不等於能阻止外部查資料；施測仍由教師監考，不新增「切換視窗＝作弊」之類判定。

## 3. 教師操作流程

- 建立兩場測驗，明確指定kind=pretest／posttest、班級、固定7題、時間及結果公布設定；不得僅憑單元名稱推斷測驗模式。
- 題庫驗證完成後發布不可變試卷快照，確認7組概念配對與前後測／練習題ID沒有重複。
- 看名冊狀態：未開始、作答中、已交卷、已到期、缺考；另看存檔／交卷異常，方便處理斷線。
- 教師按「開放」後，學生才可開始。每班有最晚開始與收卷時間，後測預設不能提前進入。
- 交卷或收卷截止後不得修改原答案、原分數。更正題目與重新批改須建立批改修訂並留理由，不覆蓋原始紀錄。
- 技術故障如需補考，教師明確授權另建補考場次，保留原場次與理由，報表標示補考；不直接刪除已交卷紀錄、解除一次限制後覆寫。
- 分數與解析預設後測全場收卷後統一公布。是否列入學期成績另行設定，不因研究／診斷目的而抹除實際測驗分數。

## 4. 後端必須強制的規則

### 4.1 試卷與答案隔離

- 正式測驗新增獨立assessment／session流程，不直接以一般Unit完整測驗或現有review複習考代替。
- 開始測驗只回傳本場固定試卷的題目ID、題幹、選項與必要圖檔；使用白名單DTO，不回傳answer、解析、引導式解析、答案來源或教師註記。
- 正解與解析保留後端私有快照。教師題庫編輯／預覽須驗證教師身分，學生不能以draft、version等參數取得它。
- 現有getBank會回傳完整Question物件；新增測驗題庫不得經此入口公開。getHistory、getReports與研究API也須檢查是否可能提早洩漏逐題正誤、score或解析。
- 既有Firestore規則已全面拒絕前端直讀寫，應保留；所有新測驗資料經受驗證的Functions存取。僅改按鈕或畫面不可視為通過。
- 學生進行一般練習時，後端也必須排除14題；不能只靠前端篩選。包含getBank、submitAttempt、submitMixedAttempts以及舊快照的可達路徑。

### 4.2 一次作答、恢復與併發

- 以courseId＋assessmentId＋uid建立唯一正式場次索引，UID來自登入token；不能由客戶端任意指定。
- 開始操作在交易內檢查名冊、班級、開放狀態及是否已有場次。刷新／重複點擊返回同一場次，已交卷不得再開場。
- 題序、選項順序與試卷版本在首次開始時固定，重進不重新抽題或洗牌；不同學生可有不同固定排列。
- 選答保存使用後端修訂序號，拒絕舊版本覆蓋新選答。同帳號多分頁不得產生第二份正式試卷；須測試衝突提示與恢復流程。
- 正式提交使用唯一session與冪等操作，同一交卷重試只回傳同一收件證明，不產生第二成績。

### 4.3 時間、交卷與批改

- startedAt、submittedAt與有效期限採伺服器時間。有效期限=min(開始時間＋限時，該班收卷時間)；client倒數僅供顯示。
- 到期後拒絕新選答；以截止前最後成功保存的選答自動交卷批改，未答題0分。尚未開始者記缺考，不當成已考0分。
- 斷線時提示哪些答案未保存；恢復只續原場次及剩餘時間，不重新計時。後端收件與已保存答案是判定依據。
- 自動收卷採後端定期處理到期場次，並在讀取／提交時惰性補結算；不能依賴學生瀏覽器一直開著。排程須可重試、不重複批改。
- 後端用凍結快照批改，不採信client score、correct、duration或聲稱的完整作答。只接受本試卷題目／選項；未答可計0，不能讓任意7題冒充完整卷。
- 逾時與手動交卷競爭時，交易保證只結算一次。截止後的選答不納入正式成績。
- 測驗不呼叫一般練習applyAttempt／updateWrong，不更新最高分、錯題複習池或練習達標；測驗完成狀態依已交卷判定，與答對比例分開。

## 5. 資料與 API 草案

獨立assessment設定與私有snapshot；每名學生獨立session及不可變final submission。資料中保留courseId、assessmentId、kind、pairSetVersion、snapshotHash、uid、classId、questionOrder、optionOrder、startedAt、expiresAt、submittedAt、submitReason、保存修訂序號、原始選答及批改修訂。

| 功能 | 草案 API | 權限與要點 |
|---|---|---|
| 發布／開放／關閉 | publishAssessment／setAssessmentState | 教師；班級設定、不可變快照 |
| 查看狀態 | getAssessmentStatus | 學生僅本人狀態；教師限所管理課程 |
| 開始或恢復 | beginAssessment | 學生；交易建立唯一場次 |
| 保存選答 | saveAssessmentAnswers | 學生本人；期限／修訂序號／選項驗證 |
| 交卷 | submitAssessment | 學生本人；冪等、伺服器批改 |
| 收卷 | finalizeExpiredAssessments | 後端排程／內部流程；到期採保存答案 |
| 成績與解析 | getAssessmentResult | 本人或教師；公布前學生僅收件狀態 |
| 成績匯出 | exportAssessmentResults | 教師；前後測配對、缺考與補考標記 |

實際命名可於實作時調整；安全與驗收要求不能只用前端替代。既有普通練習與資料讀取行為保留，測驗分支由明確型別及後端檢查控制。

## 7. MI 題庫與現況

- 完整成品83題＝前後測14＋三類國考練習47＋互動教材22；正式測驗需由同步／匯入流程分流14題進私有測驗來源，不能先全部當一般練習發布。
- 已讀線上Sheet：目前同步分頁僅22題，D2:D12的次單元含逗號；表內課程代碼115-MI與現有分頁／平台課程115-1-MI-國考精準對焦不一致。須先統一MI課程代碼並補入測驗與練習來源，不能改AP2檔。
- 不因前後測名稱相同就自動搬移或刪除題目；教師明確指定來源分類及測驗kind後才轉入私有快照。已曝光來源須標記並由教師決定是否更換施測卷，不假裝仍為未曝光。
- 原22題檔保持原樣；完整83題檔僅曾依教師授權去次單元逗號。新增測驗規則不修改題幹、選項、正解。

## 8. 實作與驗收順序

1. 先確認本規畫的施測政策（每次8分鐘、一次正式交卷、後測整場結束後公布）與班級實際時段；整理不含答案的學生／教師流程preview供審閱。
2. 另開MI功能分支，新增模型、私有快照、交易與API，先測後端。適用共用程式碼，但本次不合併／部署AP2。
3. 新增學生專用測驗畫面、教師監考與成績頁；加入名冊與班級權限、前後測隔離及匯入分流。
4. 模擬學生測試與1280／390畫面驗收；確認歷史API、普通題庫API及公開產物無測驗答案洩漏。
5. npm run check全部通過；教師核可後才按MI專用流程部署，正式施測前用測試班實測。不把網站1.7.1既有部署授權視為新模式自動上線授權。

最低驗收：
- 刷新、雙分頁與重複開始只得到一個session；已交卷無法重考。
- 截止後保存／提交遭拒或取得同一到期結果；改client時間不能延長。
- 斷線恢復原場次，倒數不重置，超時採已保存答案；未保存有清楚提示。
- 重複交卷、併發交卷與排程收卷只產一份不可變成績。
- 客戶端竄改score、correct、題目ID、選項、version或他人UID不影響批改且越權被拒。
- 學生所有API公布前不含答案、解析、逐題正誤／分數；舊getBank、一般練習提交與getHistory不可繞過限制。
- 缺考與0分區分，空白交卷仍有效；全錯也標已交卷，不要求達標或重做。
- 測驗不污染最高分／錯題／練習完成度；普通練習原有測試全過。
- 教師補考與更正有理由／修訂，不覆寫原始結果；前後測報表配對與差值正確。
- 普通練習與考卷題目互斥，正式快照發布後Sheet變動不改已開始的場次。
