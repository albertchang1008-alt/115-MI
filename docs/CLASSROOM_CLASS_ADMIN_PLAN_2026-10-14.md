# 特定班級課堂互動與最高管理者控制規畫

日期：2026-10-14。教師要求：有需要的教師可對特定班級使用，教師本人為最高管理者、可控制。本文是規畫，未實作或變更權限、未操作資料、未發布。

## 1. 已有功能與缺口
- 1.9.0已有課程層級classroomInteraction開關、course.teacherIds授權、每輪classIds勾選、倒數／加時／結果／每人一票。
- 後端只允許課程名單內的班級；學生讀題與送出都依伺服器確認的本人班級核對，不能靠前端或改網址越班。
- 現在所有課程班級預設勾選，教師授權也只有課程層級，沒有最高管理者的班級委派表；常駐卡未顯示本輪班級名稱。
- 現在每課程只有一個current輪次；開新輪會關舊輪。不同班級的兩位教師不能同時各開一輪。這是現況限制，不宣稱已有跨班獨立場次。

## 2. 權限與控制層級
| 身分 | 可控制範圍 |
|---|---|
| 最高管理者（教師本人） | 檢視各課程班級、授權／撤銷教師、設定哪些班可用互動、指定教師可操作的班級、查看目前場次並結束、檢視稽核紀錄 |
| 獲授權的課程教師 | 在管理者允許的班級中選擇本輪參與班級，開放／加時／結束／查看該授權範圍結果；不能擴增權限或操作他人班級 |
| 學生／test學生 | 只參加本人所屬且已開放的班級輪次，送出後鎖定；未授權班級看不到題目、不得作答 |

最高管理者不能由前端勾選、自稱身分、名冊欄位或網址取得。正式實作時須確認本人Google UID，透過受信任後端設定授權；不把帳密或權限名單放公開網站。MI與AP2為不同專案，跨站授權須分別處理，不因MI設定自動改AP2。

本規畫只控制課堂互動；不自動擴張到正式前後測、題庫、名冊與成績的修改權限。

## 3. 管理者操作
管理頁新增「課堂互動授權」，以課程→班級排列：班級、允許使用／停用、授權教師、目前狀態、目前輪次、已收人數。教師列表只顯示可管理此課程的教師，避免任意信箱直接取得存取權。

例：管理者允許教師甲使用N551、教師乙使用N552；test只給驗證人員；不需要的班級維持關閉。教師甲選單只出現N551，不能選N552或test。管理者可查看全部已授權班級。

有效權限同時須滿足：課程已允許互動＋管理者已允許該班＋教師已被委派該班。教師若不想使用，保持未開輪次即可，學生照常用原課程。

停用或撤銷若影響開放場次，頁面先列出受影響班級／輪次，管理者確認後後端以交易更新授權並結束受影響輪次，立即阻擋新作答。歷史作答與統計保留，不清空、不刪除；不影響其他班級。所有更動記操作者UID、時間、原因與變更前後值。

## 4. 教師上課操作
1. 選課程與本次授課班級，首次不預選全部班級，至少選一班才可開放。
2. 進到有互動的投影片，選倒數0／30／60／90／120／180秒（預設60）。
3. 開放前顯示「N551｜題目名稱｜60秒」，確認範圍後開放。
4. 常駐列顯示「N551｜開放中｜第n輪｜已收x／符合資格人數｜剩餘秒數」，只顯示班級與人數；顯示＋30秒與結束按鈕。
5. 切換投影片保留目前輪次；跨題替換需確認，確認中顯示班級／舊題／新題，不能誤關其他班級場次。
6. 結束後只看本次授權範圍的結果，亦可查該班歷史。投影不顯示姓名、學號與個別答案。

開放後不能直接改本輪班級；要變更先結束再開新輪，確保分母、作答資格與歷史一致。再投一輪仍須確認班級，不自動擴增。多班共同上課可由同一教師選自己獲授權的多班，總分母為這些班級啟用名冊合計，分班統計另列。

## 5. 學生端
只依已驗證的登入身分與班級取得題目；前端不傳入自行宣告的班級作為權限依據。參與班看到倒數、選項、送出鎖定、到期與加時狀態；其他班看不到該輪題目與統計。班級功能未允許時隱藏互動區，允許但未開放時顯示等待教師開放。

倒數仍以後端為準，既有3秒寬限、成功重送不重複計票、加時恢復尚未送出作答均保留。所有互動不計正式成績、不計單元完成度。

## 6. 分班獨立場次設計（後續開發）
若需要多位教師同時教不同班，必須把目前課程單一current入口改為按班索引；只加班級勾選無法做到。

建議保留既有classroomRounds與responses，不搬移歷史；新增課程下班級狀態索引classroomClassState/{classId}（提案名稱，尚未存在）。新輪classIds仍保存完整參與範圍；開輪時交易一次讀取所有目標班級入口與目前輪次，再檢查教師授權並寫入。不同班可並行，同一班同時只能有一輪；重複開放／兩教師競態皆由後端拒絕或要求明確替換，不能靜默蓋掉。

多班合併輪次若已有作答，任何替換或管理者撤權都先完整處理該輪，不把同一輪拆成兩套統計；畫面先提示所有受影響班級。班級權限及輪次控制在同一交易重新檢查，避免已撤權教師沿用舊畫面開輪或加時。

舊輪讀取相容：優先找本人班級的新入口；未建新入口才依舊current＋classIds判定。處理舊開放輪前須確認教師已結束，不能在正式上課中自動搬資料。此改版另寫遷移／回退規格，不使用先前MI migration腳本重跑。

## 7. 建議開發順序與驗收
第一階段：管理者班級委派、後端權限、教師班級提示／預設不全選、常駐列班級、分班歷史與稽核。沿用單一current時畫面明示同課程僅一輪，同時有其他班上課時禁止無提示替換。
第二階段：若確定有不同班同時上課需求，再加入班級獨立入口與並行交易。完成前不得承諾兩教師不同班同時開輪。

驗收矩陣：
- test班：開輪／倒數到期／＋30秒／手機送出與重整鎖定／結束與歷史。
- 權限：教師甲只能N551；教師乙只能N552；未授權教師、偽造classId、過期授權都拒絕。
- 範圍：N551與N552隔離讀取、送出與報表；目前正式班僅唯讀，寫入驗收使用合成班級或經授權測試環境。
- 競態：同班同時開輪只能一筆成功；不同班在第二階段可並行；多班共同輪分母與票數一致。
- 管理者：授權／撤銷／停用正確生效、只影響所選班級、歷史保留、稽核完整。
- 回歸：不改正式前後測、題庫、名冊與成績；兩站完整check零失敗零跳過，1280／390截圖、投影隱私檢查，再交Claude複驗與教師核准。
